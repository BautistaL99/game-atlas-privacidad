# Game Atlas V267 — approved batch automation

The public community/news updater remains independent. The discovery job produces `review-queue/proposals.json` as an artifact; it is **not** a publishable feed. Candidate categories, IDs, translations, source claims and image rights require review. Missing information stays missing; no fake maps, screenshots or statistics.

To approve a batch, review its exact contents against the sources and installed catalog, then merge a PR containing only `automation/approved-batches/pending.json` and any reviewed image bytes at their SHA-256 path. This file must have ownerDecision APPROVED_BY_OWNER, baseRevision equal to the current approved feed revision, a unique reviewId, and changes with status reviewed, schema-compatible IDs, categories, translations and sources. See the existing signed parts in updates/approved-parts for field examples. An image must be owned/licensed, have rights evidence, translations for alt text and SHA-256. Optionally imageDownloads maps a reviewed change ID to {url,sha256}; only an explicitly approved licensed image on gta.wiki/images with exact matching hash and valid bounded media is downloaded. No third-party image license is automatically inferred from metadata. An add ID must be reviewed against the bundled/community catalogs; map evidence is separately reviewed.

A one-time secret ATLAS_V265_SIGNING_KEY (base64 of an unencrypted PKCS#8 PEM Ed25519 private key) must be installed by the owner from their local encrypted key. Never commit or paste that secret into a chat. The publisher checks the key against the last signed feed before writing. Trust repository write access and workflow changes accordingly. Without a pending batch, no signing key is accessed; without a signer, no new approved batch is published.

The workflow verifies the exact R4 schema hash, runs tests, checks existing signed parts and images, merges cumulatively, signs a segmented index, and pushes only approved data. A stale base revision is rejected; if main changed during execution the push is aborted. Scheduled at 10:53 UTC; also triggered by merging an approved pending batch. Manual workflow dispatch defaults to dry run. Do not call this "working in installed Android/iOS" until tested on those clients.
