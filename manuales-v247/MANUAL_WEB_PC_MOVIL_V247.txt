3. QUÉ HACE EN PC Y EN UN CELULAR
Es el mismo catálogo y lógica compartida, con CSS responsivo.
PC: conservar topbar, menú, comparación y disposición habitual; las sugerencias quedan en flujo del documento para que no tapen resultados.
Móvil: el teclado no debe bloquear sugerencias, panel de filtros y editor; barra de desplazamiento del área del mapa, modal a pantalla completa, controles de zoom, marcadores y rutas.
Navegación de categorías de Explorar y Noticias: retroceso al nivel padre esperado; no enviar al inicio al salir de una subcategoría.
No es una “app por país”: idioma inicial según idiomas preferidos del navegador/dispositivo; si no hay ES/EN/PT, fallback EN. Elección manual 'vi_demo_locale' persistente.
Mismo funcionamiento de noticias y fichas que las aplicaciones nativas, sujeto a navegador, políticas de red y caché.

4. PONER EN MARCHA EN UNA PC SIN PUBLICAR
Requisitos: Windows/macOS/Linux, navegador moderno y un servidor HTTP local. No hace falta un dominio para inspeccionar la interfaz. En Windows con Python instalado:
  (desde la carpeta donde están 'app/' y estos TXT)
  python -m http.server 8765
  abrir en Chrome: http://localhost:8765/app/
Alternativa: npx http-server . -p 8765 (si Node y npx están disponibles; verificar comportamiento de rutas/recursos).
No abrir app/index.html con file:// como test de producción: fetch, módulos, cache, CORS y service worker pueden comportarse distinto.
Con servidor local la interfaz y contenido empaquetados funcionan, pero feeds nuevos requieren conexión y HTTPS permitido. Usar consola F12 > Network/Console para revisar errores.
Cerrar el servidor: Ctrl+C. Esta vista local NO publica, no reemplaza Firebase, no habilita descargas de tiendas ni toca datos de otros usuarios.

6. NOTICIAS, WIKI, SEO Y PUBLICACIÓN DE CONTENIDO
El frontend escucha dos feeds Ed25519 y los actualiza cuando vuelve a estar visible, aparece conexión y periódicamente (según configuración).
Oficial y comunitario son dos caminos con validaciones distintas. No editar feeds a mano sin firma válida.
El publicador actual está en el repo público main bajo workflow 'v210-free-scheduled-catalog.yml' con scripts de automation/.
Cuando cambia un feed firmado, el sitio puede mostrar nuevas entradas sin reemplazar app/index.html. El HTML/SEO estático puede requerir su proceso de regeneración según el workflow.
El sitio web en producción también debe comprobar redirecciones, canonical, sitemaps, privacy.html, atribución del mapa y licencia. No eliminar avisos de obra promocional ni fuente comunitaria.
No confundir un feed descargable con veracidad del contenido: cada fuente conserva su categoría editorial.

7. COPIA Y RESTAURACIÓN DE MI PARTIDA EN WEB
Se guarda en localStorage vinculado al ORIGEN de la web (GitHub Pages != Firebase != localhost). Abrir un dominio diferente no trae automáticamente favoritos, completados ni marcadores.
Desde Mi partida, exportar el archivo JSON, guardarlo en lugar seguro, abrir la instalación/origen de destino e importar mediante la herramienta incorporada. Verificar el número de marcadores, favoritos y rutas antes de descartar copia.
No borrar localStorage, cookies o datos de sitio por un problema visual sin respaldar. Actualizar CSS/JS en el mismo origen normalmente conserva la partida; no es garantía frente a limpieza de datos.
La función 'partida-transfer-v225.js' da instrucciones de transferencia a Android/iOS; no realiza migración automática silenciosa de almacenamiento entre navegadores y apps nativas.

9. DIAGNÓSTICO SI ALGO FALLA
- Página blanca/404: comprobar carpeta app/ y ruta /app/, index.html, referencias relativas y consola. Si falta un asset, falla precache.
- Sigue versión vieja: mirar pestaña Network de DevTools, service worker app/sw.js y caché del sitio, no borrar localStorage indiscriminadamente. El SW usa network-first para JS/CSS/HTML y mantiene assets para offline.
- No aparecen noticias: revisar https://bautistal99.github.io/game-atlas-privacidad/updates/catalog-envelope.json y /updates/community-envelope-v205.json, validación, cron y Console. No desactivar firma Ed25519.
- Falta ficha: revisar categoría permitida, revisión wiki, origen y estado de verificación; no crear un hecho no verificado.
- No sale el mapa: revisar imagen local, permisos, tamaño y attribution; si remoto firmado no disponible vuelve al empaquetado.
- Popup/touch/teclado: repetir con normal/fullscreen y rotación, verificar z-index de CSS V247 y si las sugerencias ocupan flujo normal.
- El comparador no muestra números: las fichas probablemente no aportan estadísticas comparables; comprobar source, no inventar métricas.
- Falta contenido después de instalar Android: cliente nativo se reconstruye por separado, no hereda la web publicada.
- Pérdida de partida al usar otro navegador: son orígenes locales distintos; restaurar archivo de copia.
